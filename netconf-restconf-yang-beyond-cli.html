NETCONF / RESTCONF & YANG — Beyond CLI Automation

Screen-scraping CLI with regex got us surprisingly far. But 'surprisingly far' is not an engineering strategy. Model-driven management is how automation stops being fragile.

The problem with CLI automation

Ansible playbooks full of ios_command and TextFSM templates work — until an OS upgrade reorders a column, or a config merge does something subtly different from what the template assumed. CLI is a human interface. Automating it means parsing prose.

YANG models flip this: the device exposes a typed schema (interfaces, BGP, ACLs) and NETCONF/RESTCONF are the transports for reading and writing structured data against it. No parsing. Validation before commit. Rollback as a protocol feature, not a hope.

What changes in practice

  • Candidate datastores and atomic commit. NETCONF lets you stage a config, validate it, and commit with confirmed-commit rollback timers. Half-applied changes — the classic CLI failure mode — disappear.
  • Structured operational state. GET on a RESTCONF path returns JSON you feed straight into your tooling. Your monitoring and your automation finally share one data model.
  • Vendor-neutral intent (mostly). OpenConfig models cover the common 80%. The remaining 20% is native models — still structured, still typed, just per-vendor.

The migration path that works

You do not rewrite your automation estate in one quarter. The sequence I recommend:

  • Read-only first. Replace your "show command + parse" inventory and audit scripts with RESTCONF GETs. Zero risk, immediate payoff.
  • Validate with pyATS/Genie. Use model-driven state retrieval as the assertion layer for every change — pre-check, change, post-check, diff.
  • Template into models. Move your Jinja2 from CLI snippets to YANG-shaped payloads. The templates get smaller because the device does the validation.
  • Git as the source of intent. Configs become structured documents in a repo; pipelines render, validate against a twin, and push via NETCONF. That's GitOps for the network, and it composes naturally with the AI-agent tooling I've written about elsewhere.
Honest caveat: YANG support is uneven across platforms and the learning curve is real — pyang, model trees, and XPath filters are a different skill set from CLI mastery. Budget the ramp. It pays back the first time a confirmed-commit timer saves you from a locked-out core switch.
