Splunk for Network Telemetry — Capacity Planning to Detection Engineering

I deployed a full Splunk stack — forwarders, indexers, search heads — for a government-scale network. The hard part was never installation. It was sizing honestly and turning indexed data into decisions.

Capacity planning: the numbers that actually drive sizing

Network telemetry is high-volume, low-value-density data. Sizing starts with brutal honesty about ingest:

  • Measure, don't estimate. Run representative syslog/NetFlow through a test pipeline for a week. Firewalls are the usual surprise — a busy NGFW with full logging can emit tens of GB/day on its own.
  • Daily ingest drives license; search load drives hardware. Indexers scale with GB/day and replication factor; search heads scale with concurrent users and scheduled searches. Undersized search tier is the most common failure I see — dashboards crawl while indexers idle.
  • Retention is a tiering decision. Hot/warm on fast storage for the investigation window (30–90 days), cold/frozen for compliance. Decide retention per index, per sourcetype — not one global number.

Onboarding network data properly

Heavy forwarders (or syslog-ng/SC4S in front) for UDP syslog termination, universal forwarders where you can install them, and disciplined sourcetyping — cisco:asa, pan:traffic, cisco:ise — so field extractions and CIM compliance work out of the box. Time spent normalizing at ingest pays back tenfold at search time.

From dashboards to detections

  • NOC views: interface error/discard trends, BGP flap timelines, config-change feed correlated with incident start times. The "what changed in the last hour" panel resolves more P1s than any other.
  • Security detections: ISE auth-failure bursts by endpoint, firewall denies to new external destinations, impossible-travel on VPN logins, NetFlow beaconing patterns. Each detection gets an owner, a runbook link, and a tuning log.
  • Capacity intelligence: license-usage-by-sourcetype reports so growth is anticipated, not discovered at the license wall.
A SIEM full of unsearched data is an expensive archive. Define the ten questions you must answer in an incident's first ten minutes, and build the data onboarding backwards from those questions.
