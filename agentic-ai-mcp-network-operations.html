Agentic AI & MCP for Network Operations — From Intent to Autonomous Remediation

Network automation has spent a decade translating CLI into YAML. The next leap is different in kind: AI agents that reason about the network, propose changes, validate them in a lab, and push them — with a human approving the blast radius.

Why MCP changes the integration problem

Every NetOps AI demo dies at the same point: integration. The model can write a beautiful BGP policy, but it can't see your NetBox, can't run show commands, and can't open a change ticket. The Model Context Protocol (MCP) fixes exactly this. Instead of writing one-off glue code for every tool, you expose each system — NetBox, your firewalls, your routers, Grafana, Gitea — as an MCP server with typed tools the model can call.

In my lab I run a local LLM behind an orchestration layer with MCP servers for device CLI execution, NetBox source-of-truth queries, and an EVE-NG digital twin. The agent's loop is simple: read intent → query source of truth → draft config → validate in the twin → request approval → push → verify.

The architecture that actually works

  • Source of truth first. The agent never invents IPs or VLANs. Every object comes from NetBox via an MCP tool call, so hallucination is structurally impossible for inventory data.
  • Read-only by default. Diagnostic tools (show commands, log queries) are unrestricted. Anything that mutates state goes through a separate, gated tool with an explicit approval step.
  • Digital-twin validation. Before any production push, the candidate config is applied to an EVE-NG replica and verified with pyATS — interface state, routing adjacencies, reachability.
  • Human-in-the-loop on blast radius. The agent computes which devices, VRFs, and policies a change touches and presents that as the approval artifact. You approve impact, not syntax.

What agents are good at today

Triage is the killer app. Feed an agent a syslog burst, let it pull interface counters, BGP state, and recent commits, and it will correlate cause far faster than a tier-1 engineer paging through four dashboards. Closed-loop remediation works today for a narrow, well-defined class of faults: flapping interfaces, certificate expiry, config drift against the golden template.

Rule of thumb: let agents own anything you would trust a junior engineer to do with a runbook. Keep architecture decisions, security policy, and anything touching the underlay behind human approval.

Where to start

Don't start with remediation. Start with an MCP server over your source of truth and a read-only CLI tool, and let the agent answer questions: "Which firewall rules reference this decommissioned subnet?" The ROI is immediate, the risk is zero, and it builds the trust you'll need before you ever let it commit.
