DevSecOps in Network Pipelines — SAST, DAST & Policy as Code

Once your network config lives in Git and ships through a pipeline, it inherits a superpower: every security control that software earned in the last decade can now gate your changes too.

Infrastructure code is still code

Ansible playbooks, Jinja2 templates, Terraform for cloud network, YANG payloads — all of it is code, and all of it can carry vulnerabilities: hardcoded credentials, permissive ACL templates, debug features left enabled. Shifting security left means catching these at commit time, not in a quarterly audit.

The pipeline stages that matter

  • SAST for IaC. Linters and static analyzers scan templates and playbooks on every merge request: secrets detection, dangerous module flags, known-bad patterns (any/any rules, disabled TLS verification). Fail the build, not the network.
  • Policy as Code with OPA. Open Policy Agent evaluates rendered configs against organizational rules written in Rego: "no firewall rule without a ticket reference," "no SNMPv2 anywhere," "management ACLs must include only these prefixes." Policies live in Git, are versioned, and are testable — the compliance spreadsheet becomes executable.
  • Validation in a digital twin. The DAST equivalent for networks: deploy the candidate config to an EVE-NG/containerlab replica and run active checks — pyATS state assertions, reachability probes, even authenticated scans against management planes.
  • Post-deploy verification and drift detection. The pipeline isn't done at push. Scheduled jobs diff running state against intended state and open tickets on drift — which is also your tamper-detection control.

Compliance becomes a by-product

When every change carries a ticket ID, passes signed policy gates, and leaves an immutable pipeline log, your PCI-DSS and ISO 27001 evidence collection turns into a query instead of a fire drill. In the vulnerability-management pipeline I built on my own lab server (n8n + NetBox + Gitea + Prometheus), the same pattern extends to CVE response: new advisory → affected-device query from source of truth → prioritized remediation MR → validated → pushed.

Start small: one OPA policy ("no rule without an owner tag") enforced on one firewall's rulebase. The cultural shift — engineers seeing a policy gate explain why it blocked them — is worth more than the control itself.
